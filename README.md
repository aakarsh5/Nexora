# Nexora

Nexora is a backend-focused project being built incrementally to practice and demonstrate modern backend development concepts, API design, data persistence, validation, and eventually database integration.

## Current Status

**Version:** `v0.1`

The current version implements a basic user management system using a JSON file as temporary persistent storage.

### Implemented

- User data initialization
- Automatic creation of `users.json`
- Automatic user ID generation
- Add new users
- Search users by name
- Search users by email
- Update user name
- Update user email
- Unique email validation
- Delete users by ID
- Persistent storage using JSON

## Current Data Flow

```text
Application
    ↓
UserRepository
    ↓
users.json

```

The repository follows the basic persistence pattern:

Load JSON
↓
Modify Python data
↓
Save JSON

User Data

Each user is stored with:

{
"id": 1,
"name": "Aakarsh",
"email": "aakarsh@example.com"
}

All users are stored in data/users.json:

{
"users": [
{
"id": 1,
"name": "Aakarsh",
"email": "aakarsh@example.com"
}
]
}

The user ID is automatically generated by the application and is used to uniquely identify a user for update and delete operations.

CRUD Operations
Operation Current Approach
Create add_user(name, email)
Read/Search get_user(name=...) / get_user(email=...)
Update update_user(user_id, name=..., email=...)
Delete delete_user(user_id)
Search

Searching by name may return multiple users:

Search: Aakarsh

ID Name Email
1 Aakarsh aakarsh1@example.com
5 Aakarsh aakarsh2@example.com
8 Aakarsh aakarsh3@example.com

The returned ID can then be used to update or delete the specific user.

Storage

For the current development stage, Nexora uses a JSON file instead of a database.

This is intentional so that the fundamentals of:

Python objects
Dictionaries and lists
JSON serialization/deserialization
CRUD operations
File persistence

can be understood before introducing a database.

The project will eventually move to a proper database-backed architecture.

Each component is implemented, tested, understood, and committed incrementally so that the underlying concepts and architectural decisions remain clear.
